## 1: GPU radix sort not implemented; renderer falls back to CPU sort

+++
status: closed
priority: medium
kind: none
labels: renderer
created: 2026-08-20T16:58:49Z
updated: 2026-08-20T17:04:15Z
closed: 2026-08-20T17:04:15Z
+++

The --sort gpu path prints a note and uses the CPU back-to-front sort instead. The reference GPU renderer (SplatGPUSort.metal / GPUSplatSortComputePass) does a cull+key pass, a 4x8-bit radix sort, and an indirect draw entirely on the GPU. Port this so large clouds don't pay the per-frame CPU sort cost.

- `2026-08-20T17:04:15Z`: Implemented as a GPU bitonic sort (src/sort.wgsl + gpu_sort in sort.rs): build_records computes a depth key per splat, log^2(n) bitonic_step passes order them farthest-first, extract_indices fills the draw index buffer. Not the reference's tile radix, but fully on-GPU and no atomics/subgroups. Golden test covers both sort paths (RMSE < 0.006 vs reference). Left a ponytail note to swap in a radix if sort time dominates.

## 3: Splats stored as f32 (64 bytes), not f16-packed like the reference

+++
status: closed
priority: low
kind: enhancement
labels: perf, effort:l
created: 2026-08-20T16:58:49Z
updated: 2026-09-02T19:59:25Z
closed: 2026-09-02T19:59:25Z
+++

GpuSplat is 64 bytes of f32. The reference SparkSplat is a 32-byte half-precision struct. Packing to f16 halves buffer size and bandwidth. Verify visual parity after packing.

- `2026-09-02T19:44:08Z`: Reviewed: packing GpuSplat to f16/32 bytes touches both WGSL shaders and the public GpuSplat API, and correctness of the precision loss can only be judged against the reference goldens — the golden-test .ply sources aren't present on this machine. Punting. Unblocker: make the golden splat files available (tests/golden.rs SPLATS_DIR), then this is safe to attempt.
- `2026-09-02T19:59:25Z`: GPU splat buffer now packs to 24 bytes (f16 position/scale/rotation via unpack2x16float, rgba8unorm color via unpack4x8unorm) — smaller than the reference's 32-byte SparkSplat. GpuSplat stays f32 as the CPU-side API; packing happens at upload. Sort shader reads packed positions. Validated: lion.v3.spz renders with RMSE 0.0008 vs the f32 build (golden threshold 0.02); cpu/gpu sort parity test still passes.

## 7: Renderer rebuilds shader modules and pipelines on every render

status: closed

kind: enhancement
labels: perf, effort:m
created: 2026-09-02T18:59:04Z
updated: 2026-09-02T19:40:46Z
closed: 2026-09-02T19:40:46Z
+++

Renderer is documented as 'create once, render many' but render_async recreates the shader module, bind group layout, pipeline layout, and render pipeline per call. gpu_sort likewise compiles its WGSL and three compute pipelines on every sort. ## 23: GPU frustum culling with indirect draw, controllable from the CLI

+++
status: new
priority: medium
kind: enhancement
labels: perf,renderer,cli,effort:m
created: 2026-09-02T20:07:01Z
+++

The GPU sort keys every splat and the render pass draws all count instances; there is no cull pass or compacted draw count. The reference (SplatGPUSort.metal / GPUSplatSortComputePass) culls before key build and feeds an indirect draw. Off-screen and behind-camera splats currently cost sort slots and vertex-shader work. Add a frustum-cull compute pass that compacts surviving indices and drives drawIndirect, plus CLI flags to control it (e.g. --cull/--no-cull, and possibly a margin/expand factor for splat extent, since splats have nonzero radius and naive center-culling clips edge splats).
